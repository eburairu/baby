## 2025-03-20 - APIエラーハンドリングの共通化
**学び:** フロントエンドのカスタムフェッチラッパーは、Axiosのような `{ response: { status } }` ではなく、直接 `status` プロパティを持つ `ApiError` クラスをスローします。いくつかのコンポーネントでは古いAxios風の型アサーション (`error as { response?: { status?: number } }`) を使用して409エラーをチェックしており、これは型安全ではなく、実際の実行時のエラーオブジェクトの構造と一致していない可能性がありました。
**アクション:** 既存の型ガード関数 `isApiError` を使用して `if (isApiError(error) && error.status === 409)` のようにチェックするようにリファクタリングしました。これにより、型の安全性が向上し、ボイラープレートな型アサーションが排除されました。将来のAPI通信におけるエラーハンドリングでもこのパターンを一貫して適用する必要があります。

## 2025-03-20 - APIエラーメッセージの共通化（getErrorMessageの使用）
**学び:** `getErrorMessage` ユーティリティ関数が `frontend/lib/api.ts` に存在し、`ApiError` オブジェクトから適切にエラー詳細（`.info.detail`）を抽出するか、デフォルトメッセージを返す役割を持っています。複数のコンポーネントで手動で `error` からメッセージを抽出したり、単にハードコーディングした文字列を返したりするコードが見受けられます。
**アクション:** 将来の課題として、`try/catch` または `useAsyncAction` の `onError` / `errorMessage` コールバック内で、より積極的に `getErrorMessage(error, "デフォルトメッセージ")` を利用し、バックエンドから返される具体的なエラーメッセージ（400 Bad Requestの詳細など）をユーザーに表示できるようにする余地があります。
## 2026-03-21 - チャートタイトルの共通化とインライン条件分岐の排除
**学び:** `FeedingChart`、`DiaperChart`、`SleepChart` といった各チャートコンポーネントで、現在選択されているビューに基づくタイトル文字列（「7日間の推移」「生活リズム（過去7日）」「今日 vs 7日平均」）の決定ロジックが、ネストされた三項演算子としてインラインでハードコードされていました。また、Vitestで `useIsMobile` のように `window.matchMedia` を使うコンポーネントをテストする際は、`vitest.config.ts` の `setupFiles` にモックを追加しないとエラーになります。
**アクション:** ビューごとのタイトルを返すユーティリティ関数 `getChartViewTitle` を `ChartViewToggle.tsx` に切り出し、各チャートからインポートして利用する形に修正しました。また、Vitestのエラーに対処するため `window.matchMedia` のモックをセットアップに追加しました。次回以降も、複数の場所でコピー＆ペーストされている長い条件分岐を見つけた際は、関連するUI要素の近くのユーティリティとして切り出すことを検討します。
## 2024-03-24 - [useMemoの不要なESLint無効化コメントをvoid演算子で解消]
**学び:** `useMemo`などの依存配列で、定期更新（タイマーなど）を促すためだけに変数（例：`tick`）に依存させる場合、単に`tick;`と書くと`@typescript-eslint/no-unused-expressions`の警告が発生する。これを避けるために`eslint-disable-next-line`を記述するのは冗長であり可読性を下げるが、`void tick;`という記述に置き換えることで、コメントなしでスマートに警告を回避できる。
**アクション:** 今後、変数を評価するだけで使用しないことで依存を強制したい場合は、`void`演算子を使用して副作用がないことを明示し、不要なLint無効化コメントを避ける。
