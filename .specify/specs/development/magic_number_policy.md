# マジックナンバー排除規約 (Magic Number Policy)

## 概要

本ドキュメントは、Botoro におけるマジックナンバー（意味の不明な数値）およびマジック文字列（直書きされた文字列）の排除と、定数管理のガイドラインを定義する。

**現在のステータス: 策定済み（未実装）**
※ 本規約に基づくディレクトリ作成およびコード置換は、次フェーズの実装タスクとして実施する。

## 1. 原則

- **意味のある名前を付ける**: ロジックに使用されるすべての数値・設定値・固定文字列は、定数として定義する。
- **一箇所で管理する**: 関連する定数は特定のファイルに集約し、重複定義を避ける。
- **生の値を使用しない**: `if status == 200:` や `if type == "feeding":` のような記述を避け、定数や Enum を参照する。

## 2. 定数の管理場所（実装予定）

以下の構造は、実装フェーズにおいて順次作成される。

### 2.1 バックエンド (Python)
- **`app/core/constants.py` (新規作成予定)**: ビジネスロジック、バリデーション、AIパラメータ、プロトコル等の定数。
- **`app/models/enums.py` (新規作成予定)**: 記録種別、ロール、状態等の Enum 定義。
- **`app/config.py` (既存)**: 環境変数やデプロイ環境に依存する設定値（`SESSION_EXPIRE_DAYS` 等）。

### 2.2 フロントエンド (TypeScript)
`frontend/constants/` 配下に以下の構成で新規作成する。
- **`common.ts`**: API タイムアウト、画像処理、ページネーション等。
- **`ui.ts`**: Z-index, ブレークポイント, アニメーション速度等（`ui_design_system.md` と同期）。
- **`logic.ts`**: 陣痛判定、月齢計算、バリデーション閾値等。
- **`index.ts`**: 上記の集約エクスポート。
- **`frontend/types/enums.ts`**: 文字列定数の `as const` オブジェクト定義。

## 4. 実装ガイドライン（次フェーズ）

1.  **段階的移行**: 新規実装では本規約を即座に適用し、既存コードは機能単位でリファクタリングする。
2.  **型安全性の確保**: フロントエンドでは `as const` を使用し、バックエンドの Enum と型定義を一致させる。
3.  **コメントの付与**: 定数定義には必ず `JSDoc` または `Python Docstring` で意味と単位（ms, px 等）を明記する。
